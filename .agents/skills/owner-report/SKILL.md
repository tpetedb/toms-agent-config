# Owner report

The owner asked that every report carries the same things, so they never have to ask for them: a TL;DR, all open questions, rendered Mermaid diagrams where they help, and the directory and file tree. This skill is how.

## When

Any email, message or recap for the owner about work done: a status update, an end-of-run summary, a handover, "tell me when all agents are done", a morning brief, a release note. Also the recap stage of a pipeline, whose file `tac recap` writes.

## Where the content comes from

- **Open questions**: `TODO.HUMAN.md`, the owner's queue. Run `just human render --check` first; it fails when the page is behind `.human/approvals/`. A new question from this run goes in with `just human ask` before the report, never only into the report.
- **The recap file**: write the payload in the recap contract (`contracts/handoffs/recap.schema.json`) and run `uv run --frozen --no-sync --project .agents tac recap --from <payload.json>`. It writes the dated file under the recap folder with shipped, in flight, decisions and what the owner must do; never write that file by hand.
- **The tree**: `scripts/repo_tree.py`, below.

## The shape, in this order

1. **Subject**: `<project>: <the outcome in a few words>`.
2. **TL;DR**: at most six bullets, the outcome first, each with its link (pull request, release, doc). Say plainly what failed or is unfinished.
3. **Open questions**: every open item of `TODO.HUMAN.md`, as checkboxes, blocking ones first, each with the recommendation and what it blocks, plus anything new from this run. If there are none, write "No open questions."
4. **One-time steps**: exact commands the owner runs, if any.
5. **Diagrams**: one or more rendered Mermaid diagrams wherever a picture explains faster than prose: what was built and how the parts connect, a pipeline, a trust boundary, the state of open work. Author each with the `mermaid-diagrams` skill, render it with `scripts/render_mermaid.sh`, and look at the PNG before sending. One diagram per idea, about fifteen nodes each.
6. **Directory and file tree**: for every repository the work touched, the output of `scripts/repo_tree.py`, unedited. Inline when it is 400 lines or fewer; otherwise the directories-only view inline (`--dirs-only --depth 3`) and the full tree attached as `<repo>-tree.txt`.
7. **Where things are**: paths and links to the long documents, not their contents.
8. **Sign-off** with who wrote it: the model, the effort and the role.

## The tree, deterministically

```bash
python3 .agents/skills/owner-report/scripts/repo_tree.py <repo>                       # full tree
python3 .agents/skills/owner-report/scripts/repo_tree.py <repo> --dirs-only --depth 3 # overview
python3 .agents/skills/owner-report/scripts/repo_tree.py <repo> | wc -l               # inline or attach
```

It lists what git lists (tracked plus untracked, never ignored files), so secrets, env files, venvs and caches cannot leak into a report. Run it on the branch or worktree the report is about, and name that branch.

## Diagrams in a report

```bash
bash .agents/skills/owner-report/scripts/render_mermaid.sh flow.mmd flow.png   # white background, 2x scale
```

Render every diagram and read the PNG once to check it. Then deliver it the way that works:

- **Default: a report page.** An email tool that takes attachments as base64 text inside the call breaks on one wrong character, so never paste or retype image base64. Publish the report as a private page instead (a plain HTML page renders Mermaid from `<pre class="mermaid">`), carrying the diagram sources, the TL;DR, the questions and the tree, generated by a script from the same files as the email. Put the page link in the TL;DR and paste the Mermaid sources at the end of the email.
- **Inline images only when they are tiny** and the bytes come straight from a file you did not retype.

Build the email text and the page from one set of files (body text, tree output, `.mmd` sources) with a small script, so both say the same thing.

## Rules

- The plain-text body has no Markdown markers; the tree goes in as it is. On a page, the tree goes in a `<pre>` block.
- No em dashes, no emoji, plain words. Numbers, links and ISO 8601 UTC dates over adjectives.
- Never paste secrets, tokens or the content of ignored files. For a public destination, run `just private-scan` first.
- Send to the owner's own address only when they asked for an email; otherwise put the report where they asked for it.
