Single-use dispatch tokens (build condition C1): the runner issues a token bound to the run, the stage, the session it starts and the sha256 of the prompt or Workflow script it authorises, and the handoff guard spends it over the runner's socket. In a session the runner dispatched, Agent and Task need a token bound to the spawn's prompt and Workflow one bound to the registered script; a missing, altered or reused token, a runner that does not answer and a torn reply are each a deny, and a token presented with the wrong binding, another session's token included, is burned; a dispatch record naming another run or stage than the runner's own marker for the session is a deny before the runner is asked. The owner's own chat with the chief keeps its subagents as the recorded exemption. Tests cover every guard failure mode, including a hook timeout.
