The five pipelines under `.agents/config/pipelines/` (`order` with its intake and publish stages, `board`, `review`, `release`, `retro`), read through a strict schema exported to `contracts/config/pipeline.schema.json`: agent, gate, effect and human stages, gates as argv arrays never shell strings, effects only from `runner_only`, `bind` for a contract two upstream stages write and `waits_on` for a gate whose recipe a later milestone adds. `tac pipeline check` (also run by `tac check` and in CI) names the reason for every refusal, and `tac pipeline plan <name>` prints the stage order without running anything.
