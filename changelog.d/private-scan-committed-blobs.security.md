The private scan reads the committed blobs (`git grep --cached`) and only new or changed files from the working tree, so a candidate's `working-tree-encoding=UTF-16` can no longer turn a UTF-8 blob into UTF-16 in CI's checkout and hide a term; it also decodes and greps any file that opens with a UTF-16 byte order mark, which `git grep -I` skips as binary while GitHub shows it as text.
